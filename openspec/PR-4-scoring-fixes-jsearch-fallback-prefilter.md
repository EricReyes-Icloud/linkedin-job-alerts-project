# PR 4: Scoring fixes, JSearch fallback, and pre-filter

## Description

The Gemini scoring step was silently broken — `scoreJobsBatch` and `scoreSingleJob` always produced 0 for every job. The root cause was that the code fed the raw Gemini `:generateContent` envelope directly into `parseJSONWithFenceStrip`, but the actual score array lives inside `candidates[0].content.parts[].text` as a string-within-JSON, not at the top level. This PR extracts the model's text output from the envelope before parsing, and adds tolerant helpers that handle Gemini returning numeric strings despite requesting INTEGER schema.

JSearch queries were also too restrictive — stacking Colombia + remote + under-3-years + no-experience + FULLTIME + this-week often returned zero results. A strict-then-relaxed fallback now retries with fewer filters when the strict pass yields nothing. A new pre-filter step (Step 3.5) runs before Gemini scoring to exclude senior roles and non-matching tech stacks, saving quota. Description summarization further reduces token consumption by sending Gemini a keyword-focused summary instead of the full job description.

## Changes Made

### Bug fixes

- **`src/services.js`** — Added `extractGeminiText(rawText)` to unwrap the Gemini `:generateContent` response envelope (`candidates[0].content.parts[].text`), fixing the root cause where `scoreJobsBatch` and `scoreSingleJob` always scored every job 0.
- **`src/services.js`** — Added `toScoreNumber()` and `toJobIndex()` helpers that accept number or numeric string (Gemini sometimes returns strings despite INTEGER schema), clamp to valid ranges, and skip malformed entries instead of wiping the batch's score map.

### Features

- **`src/services.js`** — Added `buildJSearchQuery(keyword, strict)`, `parseJSearchResponse(rawText)`, and rewrote `fetchFromJSearch` with a strict-then-relaxed fallback. When `CONFIG.JSEARCH_STRICT_FIRST` is enabled and the strict query returns 0 jobs, a relaxed query drops `employment_types`/`job_requirements` and widens `date_posted` from week to month while keeping `country=co` and `work_from_home=true`.
- **`src/services.js`** — Added `preFilterJobs(jobs)` (exported on the `Services` module) that excludes jobs by seniority regex (`SENIORITY_EXCLUDE`) and requires at least one tech-stack keyword match (`TECH_STACK_KEYWORDS`). Logs excluded titles with reasons.
- **`src/services.js`** — Added `summarizeDescriptionForScoring(job)` producing a keyword-aware 300-600 character summary for the Gemini scoring prompt. The original `job.job_description` is left untouched for Notion/Telegram.
- **`src/pipeline.js`** — Inserted Step 3.5 calling `Services.preFilterJobs(newJobs)` between dedup and scoring, so only pre-filtered jobs reach Gemini.

### Dev tooling

- **`test-runner.js`** — Added real network timeout to curl via `-m <N>` (default 30s, configurable via `CURL_MAX_TIME` env var). The `execSync` timeout was also raised from 30000 to 120000ms as a hard backstop. Previously curl had no `--max-time`, so a hanging server (e.g., saturated Gemini returning 503) blocked the run for the full 30s execSync window.

### Configuration

- **`src/config.js`** — Trimmed `KEYWORDS` to `['javascript developer junior', 'react developer junior', 'node developer junior']`.
- **`src/config.js`** — Added `SENIORITY_EXCLUDE` regex (`/\b(senior|lead|manager|staff|principal|director|vp|head\s+of)\b|\bjava\b(?!script)/i`) and `TECH_STACK_KEYWORDS` array for the pre-filter step.
- **`src/config.js`** — Changed `GEMINI_MODEL` from `gemini-3.7-flash` to `gemini-3.6-flash` (3.7 was returning HTTP 503 high-demand errors).
- **`src/config.js`** — Added `JSEARCH_STRICT_FIRST: true` to control the strict-then-relaxed fallback behavior.

### Autogenerated

- **`.atl/skill-registry.md`**, **`.atl/.skill-registry.cache.json`** — Auto-regenerated skill registry (includes the new `pr-creator` project skill).
- **`openspec/changes/jsearch-keyword-refinement/`** — SDD change folder (proposal/spec/design/tasks) for the JSearch keyword refinement and pre-filter work.

## Impact

- **Scoring now works.** The pipeline will actually score jobs via Gemini instead of assigning 0 to everything. This is the most significant behavioral change — jobs that previously never passed the score threshold will now be evaluated properly.
- **Fewer empty runs.** The JSearch strict-then-relaxed fallback reduces the frequency of zero-result fetches when strict filters are too narrow for a given keyword.
- **Lower Gemini quota consumption.** Pre-filtering (Step 3.5) and description summarization reduce the number and size of scoring requests. Jobs excluded by seniority or tech-stack never reach Gemini.
- **More resilient local testing.** The curl `-m` timeout prevents hanging runs when external services are unresponsive, with the 120s execSync as a backstop.
- **Backward compatibility.** All new behavior is behind config toggles (`JSEARCH_STRICT_FIRST`, `SENIORITY_EXCLUDE`, `TECH_STACK_KEYWORDS`). Removing or disabling these restores the previous behavior. The `preFilterJobs` export is additive on the `Services` module.
- **Caveat.** The `extractGeminiText` function falls back to returning the raw text unchanged if the envelope shape doesn't match — this preserves any direct-JSON path but means the bug could resurface if Gemini's response format changes unexpectedly.
